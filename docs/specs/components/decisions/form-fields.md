# Form fields: decisions

- Q-1 Dedicated FormsKit and FormsDesign packages, as thought to be in FinanceTracker, or form components inside DesignKit and DesignSystem? Answer: inside, in `Forms/` folders, flat `DK` and `DS` names. A separate design package couldn't add component tokens to the complete themes without opening the `internal` primitives, and would split the catalogue; FinanceTracker itself keeps its form components in DesignKit. Validators are UtilitiesKit's (UtilitiesKit validation/validators); HomeBudgetApps FormKit binds them to `DK.FormField` (HomeBudgetApps forms/validated-fields); UtilitiesKit and DesignKit never import each other.
- Q-2 The design-system lifecycle wants `Approved` canvas pages before a component spec. Answer: draft the spec now; the four canvas pages are made next and must be `Approved` before `review-spec` approves the spec. First scope: base components and the text field; other inputs in components/form-inputs.
- Q-3 How does the field row lay out per platform? Answer: iOS stacks the row (title with qualifier, control, support text); iPadOS follows macOS. Shapes: BR-6. (canvas page Field Row, 2026-10-31) Superseded by Q-11.
- Q-4 Should the form move the focus to the first field with an error by itself when the confirm action finds errors? Answer: no, and the ViewModel can't either (Q-8): visible errors and the announcement of BR-7 point to it; a `DS.Form` option can add it later without changing Core. Shapes: Scope, BR-1, BR-4. (review-spec round 1, 2026-10-31)
- Q-5 Native controls or the canvas look exactly? Answer: native: the rounded-border text field, the system focus ring, native row widths (no fixed label column); an error draws a Border.critical border over the native one and, while focused, a Border.critical focus ring in place of the system's (the canvas error look kept, round 1 follow-up). Shapes: Data, BR-6, BR-8. (review-spec round 1, 2026-10-31)
- Q-6 What does Return do on iOS and iPadOS? Answer: the return key reads Next on every field but the last and Done on the last, which hides the keyboard; confirming stays the button's. Shapes: BR-5. (review-spec round 1, 2026-10-31)
- Q-7 Port FinanceTracker's VoiceOver announcement of an error appearing on the focused field? Answer: yes, with key `designSystem.fieldRow.error`. Shapes: BR-7, BR-11. (review-spec round 1, 2026-10-31)
- Q-8 Who owns the focus, given validation forced by focus changes (UtilitiesKit validation/validators)? Answer: the form (a SwiftUI `@FocusState` inside `DS.Form`, UI layer only); it reports each gain and loss through `DK.FormField.onFocusChange`, a closure the ViewModel builds, so Core tests call it as the UI does; no `hasFocus`, a ViewModel never moves the focus. Two-way `hasFocus` (FinanceTracker) and reported state with focus requests were weighed and rejected: both keep two sources of truth in sync by hand. Shapes: Data, BR-1, BR-4. (review-spec round 1, 2026-10-31)
- Q-9 Which field has the focus when the form appears? Answer: none, on every platform. Shapes: BR-4. (review-spec round 1, 2026-10-31)
- Q-10 Keep `isHidden` on `DK.FormField`? Answer: no: a ViewModel hides a field by leaving it out of its content (an optional field, or a section without it), so the focus order is the rows drawn. Shapes: Data, BR-1, BR-4, BR-5, BR-6, BR-14, AC-4. (review-spec round 1 follow-up, 2026-10-31)
- Q-11 Lay out the field row by platform or by size class? Answer: by the horizontal size class: the labelled row unless compact (macOS has none), stacked when compact, so an iPad in Split View stacks and an iPhone Max in landscape gets the row. Supersedes Q-3. Shapes: BR-6, AC-17. (implement-increment S2 review R-1; review-spec revalidation, 2026-10-31)
- Q-12 What happens to the focus when the size class changes while a field has it (iPhone Max rotated, Split View resized)? Answer: the field keeps the focus, its keyboard and its text, and no `onFocusChange` is called; losing it like a removed field was rejected: rotating mid-typing would hide the keyboard. Shapes: BR-4, BR-6, AC-17. (review-spec revalidation, 2026-10-31)
